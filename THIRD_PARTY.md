# Third-party components

Every component vrcore fetches, links or reads from: upstream, pinned commit, licence, how it is used and what was
changed. `tools/fetch_extern.py` holds the pins (one list for every game built on vrcore) and fetches them into a
git-ignored `extern/` folder (default `../../extern` from here, CMake's `VRCORE_EXTERN_DIR`); nothing fetched is
committed. A game's own THIRD_PARTY.md says which vrcore tag pins them and points here.

The per-device controller models are converted, not renamed (`assets/controllers/`). Each is the upstream file at the
commit in its row, with `git hash-object` blobs as listed (every file was fetched from raw.githubusercontent.com at
that commit and its blob hash recomputed). The conversion, 2026-10-15: the base colour image of each file is decoded,
flattened to opaque RGB (every one of these materials is OPAQUE), cut to 1024 px or less with a Lanczos filter where it
was larger, and encoded with KTX-Software `toktx` v4.4.2 (`--encode astc --astc_blk_d 6x6 --astc_mode ldr
--astc_quality thorough --genmipmap --assign_oetf srgb`, no supercompression) into a KTX2 file beside the glTF
binary. The glTF binary then has every embedded image and its bufferView removed and the binary chunk compacted; each
accessor's data was compared byte for byte with the upstream's, and the node, mesh and sampler lists are identical. The
result is not a glTF other viewers show textured: the image entry's `uri` names a `.ktx2` file, which only
`host/ui/controllers.cpp` reads (through `host/gpu/ktx2.cpp`; the extension `KHR_texture_basisu` is for Basis
Universal data, not plain ASTC). The decoded KTX2 files were compared with the source images through an
independent decoder (astcenc 5.7.0): PSNR 46 to 57 dB. The tools are not vendored or built into anything.
